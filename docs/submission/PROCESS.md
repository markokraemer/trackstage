# Process overview — how we went about this

## The approach

Trackstage was built spec-first and agent-driven: a human doing product judgment, a fleet
of agents doing parallel execution, and the repo — never a chat window — as the source of
truth. Nothing was implemented before it was specified, and nothing was called done before
it was checked against something outside our own opinion. The human's raw inputs are kept
verbatim and replayable: **~250 prompts across 11 sessions on two coding agents**, many of
them a screenshot plus a sentence. The result is **279 commits** across **67 logged work
sessions**, mostly inside a ~46-hour window.

## How we scoped it

swyx's walkthrough video was ingested into a timestamped transcript, a screen-by-screen
requirement analysis, and a pass on layout geometry. The 42 brief screenshots were
forensically specced by five parallel agents into per-area UI documents — every field,
pill, drawer and empty state written down before it was implemented. We mapped
Sessionboard's public API endpoint by endpoint, since an API reference doubles as a
feature census, and copied the domain language exactly — Abstracts vs Sessions, the
Draft → Pending → Accept/Decline Queue → Accepted/Declined pipeline, Tracks vs Tags,
submitter ≠ speaker — so the walkthrough maps one-to-one onto our product.

swyx's Discord clarifications amend the spec, including where they *narrow* it. He struck
six things — Accelevents integration, wiki/HTML-embed resource pages, AI-assisted review,
payments, CRM, marketing — and we did not build them, even where one was worth a rubric
point. Restraint is a product decision: the tool has to stay learnable by a non-technical
organizer in one sitting.

## The working system

Three durable memory documents, read before starting and written to before stopping:
**RULES.md** (procedural — standing directives, reversals struck through and left
visible), **DECISIONS.md** (semantic — every non-obvious decision and the alternatives
rejected), **BUILD-LOG.md** (episodic — what happened, including what failed). `SPEC.md`
is the build contract; `PROMPTS.md` is the raw-prompt corpus, regenerated by script from
the session transcripts.

Execution ran as parallel waves of subagents — five agents on the screenshot specs, an
eleven-slice UI workflow, a seven-agent parity wave, a ten-agent mega-wave — each closing
with an integrate → verify → promote loop and a named gate. Parallelism had a real cost we
logged rather than hid: agents resetting the shared dev deployment every 30–60 seconds
corrupted each other's test runs, which is why the final gate runs hermetically. And
because slice-per-agent work drifts, a reconciliation pass was mandated up front: one
agent reworks the whole app against `/design-system` as the contract.

## Verification discipline

- **Every push runs `verify`:** typecheck · lint · OpenAPI drift · 353 unit tests. Every
  promote adds the **complete Playwright flows suite** (15 specs, CFP through embeds)
  **hermetically** — an anonymous Convex backend booted inside the runner, seeded from
  scratch, no cloud data touched and no mail sent. **Retries are zero, deliberately**: a
  flaky failure has to be fixed, not converted into a green check. A release required the
  suite green **three consecutive runs**, and that third run is what caught a bulk-send bug
  stranding the tail of any send over 25 recipients. Since an SSR crash still returns a 200
  shell, the deploy job then smokes the live origin for expected *content*.
- **We ran the official eval kit against ourselves** (`swyx/killmysaas-evals`) as a
  hill-climb loop — first as a pre-build gap audit (31 covered · 18 partial · 36 gap of 86
  required items), then repeatedly against production: **86.3 → 93.6 → 94.4**
  best-per-area across the six judged areas, with every area's *worst* reading giving
  **93.4**, the floor. Both are self-reported from our own runs, not an official result.
- **Reading the verdicts mattered more than the score.** Each non-pass was classified as
  *product*, *agent-couldn't-reach*, *judge-couldn't-see* or *manual-only*, because the
  right response differs in each case. Where we had no evidence we recorded *pending*, not
  pass.
- **One point was declined.** ABS-14 (AI-assisted review) scores `not_found` on purpose —
  swyx struck it — and the 19-point Speaker-CRM bonus pool was forfeited by scope choice.
- **An independent adversarial review** by a fresh agent that had not built the product
  returned 21 findings on a P0–P3 scale, each with a repro; two were kept as reviewed
  decisions, the rest fixed, leaving no P0/P1/P2. Its P0 shows the value of an outsider:
  the production docs' OpenAPI spec named the *dev* deployment as its server, so "Try it"
  would have sent a real production key to dev — and CI could not catch it, because the
  drift check validated that URL against itself.

## What went wrong, and how it was caught

**Production sign-in went down.** `POST /api/auth/*` began 404ing. The first fix blamed the
wrong thing — a custom Worker entry added for video byte-range support — and reverting it
didn't help. Header bisection found the real cause: our proxy forwarded a plain
`x-forwarded-host`, which Convex's edge treats as a Pro-gated custom-domain lookup, so it
404'd the auth route. Fixed with a hand-rolled proxy controlling its own headers; the
innocent Worker entry was re-landed once exonerated.

**An eternal skeleton on Safari.** The email-confirmation link left the app loading
forever. Auth status gated every authenticated query on Better Auth's browser
`get-session` fetch — no timeout, and Safari parks it in the background tab a mail client
opens. It was the wrong signal anyway: the Convex client is already authenticated on a cold
load, and right after sign-in it isn't yet. Status now derives from Convex's own auth
state, and a first-run arrival is legible in the URL so the server can render it directly.

**The demo organizer nearly got email-gated.** A new verification gate plus a stale
production seed would have stranded the judge on a confirm-email screen — nearly the whole
rubric runs through that login. Our own eval agent hit it first. Reseeding fixed it; making
it permanent was the real fix: the deploy gate now signs in with the exact credentials the
login page advertises and requires the session to read back verified.

**The eval found real bugs in the half it couldn't see.** Three items came back
"unverifiable by the agent". We opened the artifacts instead of trusting the success toast,
and two were not merely unverified but wrong: bulk download shipped *every* version of a
file rather than the current one (a library is a history, a bundle is a handover), and the
public `.ics` feed folded lines by UTF-16 code units instead of octets — so an em dash
overran the RFC limit and a mid-surrogate boundary corrupted emoji into `U+FFFD` in a
subscriber's calendar. The mirror image: the judge reported buttons "covered by an
invisible overlay" that our Playwright suite clicked green every run. A sticky column
really was covering them — Playwright forces a click through where a real agent does not.

## Product judgment over metric-chasing

- **Settings IA went pages → modals → pages.** Account and workspace settings moved into
  Linear-style modals; within hours the human hit dialog-over-dialog twice and called it.
  Everything carried over 1:1 into page shells, and "nothing ever stacks" became a rule.
- **Onboarding grew a ten-step guided tour, then we deleted it.** Confetti and one welcome
  card is the whole moment.
- **A measured design win was overruled.** A petrol accent won every axis in our own colour
  analysis; the human preferred the original blue. The complaint was never the hue but how
  much chrome was wearing it, so the neutral system shipped and the accent was confined to
  five permitted places.
- **And the eval kit overruled us.** We had exempted accepted speakers from the CFP
  close-date edit lock, reading a clarification generously. The kit hard-failed it, so the
  exemption went and the recorded decision was reversed in writing, not quietly amended.

## Honest limitations

Some rubric halves can only be proven by a human — real inboxes, importing an `.ics`, a
second account — and those are an explicit manual checklist, not claimed as passing. Email
is the one thing we refused to take on trust without an inbox: every send records its
provider id, and the provider's own `delivered` receipts are what we cite.

The last run left a ranked list of eleven open defects, which we publish rather than bury.
The most expensive is a nested date picker in the "Assign a task" dialog that intercepts
clicks, leaving the task type keyboard-only. A file uploaded against a task also carries no
session association, so AV can't tell which session a deck belongs to. Custom CSS in embeds
stays deliberately excluded as an injection footgun. And the eval numbers are our own runs,
one of which hit the harness's 150-turn cap — which is why we publish a floor as well as a
ceiling — taken before the adversarial close-out. Only a fresh external run can move them.
