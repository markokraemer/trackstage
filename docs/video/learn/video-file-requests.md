### A. Screen Inventory

1. **File Requests Directory (`Portals -> File Requests`)**
   * **Purpose:** List, manage, filter, and create file collection tasks.
   * **Components:** Search bar (`Search file requests...`), `+ Create Request` primary button, status tabs (`All Requests`, `Open`, `Closed`), sort selector (`Sort by: Most Pending`), list cards with task title, count badge, target entity type, creator, and creation timestamp.

2. **Add File Request Modal (`Portals -> File Requests -> + Create Request`)**
   * **Purpose:** Define name, type, guidelines, and optional reference files for a new request task.
   * **Components:** Title input (`File Request Title *`), entity selector (`People`, `Groups`, `Sessions`), rich text editor (`Criteria / Instructions`), dropzone upload box (`Include sample file(s) with this request`), `Save File Request` button.

3. **Portals List (`Portals -> Portals`)**
   * **Purpose:** Select target participant group portals to attach tasks to.
   * **Components:** Search bar, `+ Create Portal` button, condition warning alert banner, category tabs (`People Portals`, `Group Portals`), portal summary cards with action ellipsis menu (`Edit Tasks`, `Edit Criteria`, `Copy Link`, etc.).

4. **Portal Task Configuration (`Portals -> [Portal] -> Edit Tasks`)**
   * **Purpose:** Attach forms, file requests, and pages to a specific portal.
   * **Components:** Task category widgets (`Collect Form Submissions`, `Collect Files`, `Assign Pages`), action buttons (`Assign file requests`, `Manage file requests`), configured task table (`Name`, `Alias`, `Due Date`, `Extended Due Date`, `Required` toggle, pencil/trash action icons).

5. **Assign File Request Modal (`Portals -> Edit Tasks -> Assign file requests`)**
   * **Purpose:** Select existing file requests to map to the portal.
   * **Components:** Search bar, batch selection links (`SELECT ALL`, `NONE`, `Select all`, `Clear selected`), list of checkable tasks, bottom selection counter badge, `Save` button.

6. **Edit Assigned Task Settings Modal (`Portals -> Edit Tasks -> Edit Icon`)**
   * **Purpose:** Set deadlines, display aliases, completion behavior, and rule-based assignment filters.
   * **Components:** `Alias` text input, `Due Date` calendar picker, `Required` toggle, `Make Completed Tasks View Only` toggle, `Assign By Filter` toggle with rule condition builders (field dropdown, operator dropdown, value dropdown, `+ Add filter`), `Update` button.

7. **Participant / Speaker Portal Drawer View**
   * **Purpose:** End-user portal interface to view requirements, download templates, and submit files.
   * **Components:** Left task list navigation tabs (`All`, `My Tasks`, `Sessions`), main slide-over drawer with `Details`/`Messages` tabs, status badges (`OPEN`, `Incomplete`), `CRITERIA` text, `SAMPLE DOCUMENT` download block, upload dropzone box, `Done` and `Submit` action buttons.

### B. Feature / Capability List

1. **File Collection Constraints:** File Request tasks permit strictly **one** file upload per submission task. Re-uploading replaces/updates the existing file version.
2. **Entity Scoping Types:**
   * **People:** Assigns task directly to individual contacts/speakers (e.g., contracts, agreements).
   * **Groups:** Assigns task to sponsor or exhibitor organizations (e.g., logos, program ads).
   * **Sessions:** Assigns task per individual presentation/session (e.g., slide decks).
3. **Reference File Attachments:** Organizers can attach sample/blank documents directly to the task prompt for participants to download.
4. **Conditional Task Assignment Filters:** Session tasks can be conditionally assigned using filter logic rules (e.g., `Format` `is` `Keynote`).
5. **Portal Task Configuration Controls:**
   * Toggle task mandatory/optional status (`Required` switch).
   * Define custom task display aliases (`Alias`).
   * Set task submission deadline date/time (`Due Date`).
   * Enforce view-only locking upon completion (`Make Completed Tasks View Only`).
6. **Task List Filtering:** Tasks can be sorted by pending count and filtered by lifecycle statuses (`All`, `Open`, `Closed`).

### C. Data Model Signals

* **File Request Task:**
  * `id`: UUID
  * `title`: String
  * `type`: Enum (`People`, `Groups`, `Sessions`)
  * `criteria_instructions`: Rich Text / HTML
  * `sample_file_url`: String (optional)
  * `created_by`: User reference
  * `created_at`: Timestamp
* **Portal Task Assignment (Junction Entity):**
  * `portal_id`: Foreign Key
  * `file_request_id`: Foreign Key
  * `alias`: String (optional)
  * `due_date`: DateTime (optional)
  * `extended_due_date`: DateTime (optional)
  * `is_required`: Boolean
  * `is_view_only_on_completion`: Boolean
  * `filter_rules`: Array of Objects (`field`, `operator`, `value`)
* **Participant Task Submission:**
  * `task_assignment_id`: Foreign Key
  * `participant_id`: Foreign Key
  * `uploaded_file_url`: String
  * `status`: Enum (`OPEN`, `Incomplete`, `Submitted`, `Complete`)
  * `updated_at`: Timestamp

### E. UX/UI Craft Notes

* **Layout Geometry:**
  * Sidebar: Collapsible fixed left navigation (~240px wide).
  * Main Content Area: High-density card layout with ~1200px max-width content area.
  * Modal/Drawers: Modals centered with soft dark backdrop (~600px width); Participant Task View uses a right-aligned slide-over drawer (~480px width).
* **Color Palette & Visual Hierarchy:**
  * Primary Action Buttons: Solid Navy/Blue (`#1E56E0` / `#0B2545`) for portal setup; distinct solid Orange (`#E06D1B`) for task creation save steps.
  * Status Badges: Round-cornered pills (`OPEN` in blue background with white text; `Incomplete` in light grey background with dark text).
  * Dark Contrast Modals: Primary selection modals use solid blue header banner strips with stark white titles and `X` close icons.
* **Form & Table Styling:**
  * Form labels sit directly above input fields in semi-bold grey typography.
  * Inline rule builder rows utilize full-width segmented drop-down selects (`[Field] [Operator] [Value]`) ending with an explicit `X` remove button.
