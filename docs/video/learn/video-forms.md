### Section A: Screen Inventory

1. **Forms Index Page (`Portals -> Forms`)**
   - **Purpose:** Lists all existing portal forms with submission metrics and creation metadata.
   - **Components:** Sidebar navigation, top bar event selector, tab bar (`All Forms`, `People Forms`, `Group Forms`, `Session Forms`), search bar, sort dropdown (`Sort by: Most Results`), `+ Create Form` button, form item cards.

2. **Create Portal Form Modal**
   - **Purpose:** Select entity target type for form creation.
   - **Components:** Entity option cards (`Contacts`, `Groups`, `Sessions`), `Save & Build Form` button, `Cancel` button.

3. **Edit Portal Form Wizard (`Form Setup` / `Form Questions` / `Form Settings`)**
   - **Purpose:** 3-step modal wizard to define form attributes, fields/questions, and submission email confirmation.
   - **Components:** 3-step stepper, internal `Name` & public `Title` inputs, `Section Title` & `Description & Instructions` text areas, field table with required toggles and ellipsis menus, field picker modal, rich text email body editor, step navigation buttons (`Next: Form Questions`, `Next: Form Settings`, `Save`, `Back`).

4. **Select Fields Modal**
   - **Purpose:** Field picker to assign global/event fields or create new custom fields.
   - **Components:** Filter search input, scope filter radios (`All Fields`, `Global`, `Event`), left-side available fields list, right-side selected fields list with drag reordering, `+ Create New Field` link, `Done` button.

5. **Portals Index Page (`Portals -> Portals`)**
   - **Purpose:** Lists audience portals, criteria, and assigned counts.
   - **Components:** Banner notification, tabs (`People Portals`, `Group Portals`), portal card list with menu dropdown (`Edit Tasks`, `Edit Criteria`, etc.), `+ Create Portal` button.

6. **Edit Portal Screen (`Assign Items` Step)**
   - **Purpose:** Configure tasks, forms, and file requests assigned to a portal.
   - **Components:** Stepper (`Select participants`, `Assign items`, `Configuration`, `Appearance`), task section cards (`Collect Form Submissions`, `Assign Tasks`, etc.), assigned forms summary table with `Required` toggle and edit action buttons.

7. **Edit Session Task Modal**
   - **Purpose:** Configure submission rules, due dates, edit permissions, and conditional filter rules for assigned forms.
   - **Components:** Alias field, date-time picker, `Allow edits`, `Mark as required`, `View-Only` toggles, `Assign By Filter` rules builder (`Field`, `Operator`, `Value`), `Update` button.

8. **Participant Portal View**
   - **Purpose:** Public-facing portal page for participants to complete and submit required form fields.
   - **Components:** Header banner, `Back to Homepage` button, section title/instructions, text fields with `0/255 Characters` character counters.

### Section B: Feature / Capability List

1. **Form Classification:** Form entities must target one of three entity types: `Contacts` (People/Speakers), `Groups` (Sponsors/Exhibitors), or `Sessions`.
2. **Dual Naming Structure:** Form builder supports separate internal administrative `Name` and public participant-facing `Title`.
3. **Form Questions Setup:**
   - Section heading (`Section Title`) and rich instructions (`Description & Instructions`).
   - Standard field integration support (native syncing for integrations like Grip/Swoogo).
   - Reusable field selector library with search and filtering by scope (`Global` vs. `Event`).
   - Custom field creation (`+ Create New Field`).
   - Per-question settings: Toggle required status, custom labels, custom help text (`Customize question`), conditional display rules (`Use question rules`), field level settings (`Edit field`), and non-destructive removal (`Remove from form`).
4. **Email Confirmation System:**
   - Optional post-submission confirmation email toggle (`Send Confirmation Email`).
   - Automatic PDF generation of form responses attached to confirmation email.
   - Rich text message body customization editor.
5. **Portal Assignment & Targeting:**
   - Multiple portal assignment mapping via portal management panel (`Collect Form Submissions`).
   - Per-portal title override (`Form Title Alias`).
   - Portal-level deadline setting (`Due Date` picker).
   - Target segment filtering (`Assign By Filter`) using conditional key-value operators (e.g., `Format is Keynote`).
   - Submission state controls: `Allow edits`, `Mark this form as required`, `Make Completed Tasks View-Only`.

### Section C: Data Model Signals

1. **Form Entity:**
   - `id`, `internal_name`, `public_title`, `entity_type` (`Contact` | `Group` | `Session`)
   - `section_title`, `description_instructions`
   - `send_confirmation_email` (boolean), `confirmation_email_body` (HTML text)
   - `created_by`, `created_at`, `submission_count`
2. **Form Question / Field Mapping:**
   - `form_id`, `field_id`, `question_label`, `help_text`
   - `is_required` (boolean)
   - `sort_order`
   - `question_rules` (conditional logic object)
3. **Field Registry Entity:**
   - `field_name`, `field_type` (`Text`, `Dropdown`, `File Upload`, etc.)
   - `scope` (`Global` | `Event`)
4. **Portal Task / Form Assignment Entity:**
   - `portal_id`, `form_id`, `form_title_alias`, `due_date`
   - `is_required` (boolean), `allow_edits` (boolean), `view_only_when_completed` (boolean)
   - `assignment_filters` (Array of rules: `field`, `operator`, `value`)

### Section E: UX/UI Craft Notes

- **Wizard & Modal Architecture:** Heavy reliance on multi-step wizard modals (`Edit Portal Form`, `Edit Portal`) with explicit step indicators (1 -> 2 -> 3) and standard button placement (Primary action bottom-right in orange/blue, secondary/back bottom-left).
- **Table & List Density:** Tables feature clean horizontal dividers, compact action toggles (green ON / grey OFF), and right-aligned action icon groups (`pencil`, `x`, `ellipsis`).
- **Color Palette Hierarchy:**
  - **Primary Action Accent:** Orange (`#FF5722` / `#F4511E`) for builder navigation & primary wizard actions.
  - **Brand Accent:** Royal Blue (`#1E88E5`) for primary top-level creation buttons (`+ Create Form`, `+ Create Portal`).
  - **Status Toggles:** Vibrant Green when active.
- **Form Input Design:** Inputs utilize top-aligned labels, subtle outline boundaries, full-width field containers, and explicit input character counters (`0/255 Characters`) aligned right below text boxes.
