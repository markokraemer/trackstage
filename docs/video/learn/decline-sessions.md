**NARRATION:**
There are five session statuses: Accepted, Accept Queue, Pending, Decline Queue, and Declined. Accepted is assigned to sessions that have been officially approved and will be included in the event. These sessions are awaiting review or a decision. Decline Queue is assigned to sessions that are being considered for rejection, but have not yet been officially marked as declined. Declined sessions have been officially rejected and will not be included in the event. Watch the session settings training video to learn how to create custom statuses.

## A. Screen Inventory

1. **Session Settings — Statuses** (`Sessions -> Settings -> Statuses`)
   - **Purpose:** Manage workflow statuses and sequence order.
   - **Components:** Section title, `+ Add Status` button, status list table with columns: `Name`, `Category`, `Color`, `Order`, `Sessions`, `Created By`, `Created At`.
2. **Participant Portal — My Submissions View**
   - **Purpose:** Submitter-facing list of session submissions and decision statuses.
   - **Components:** Session title cards, status pill badges (`Accepted`, `Declined`, `Pending` / clock icon for queue states).
3. **Submissions List** (`Sessions -> Submissions`)
   - **Purpose:** Primary management grid for all event session submissions.
   - **Components:** Top tabs (`Submissions`, `Forms`), filter chips, search input, `Options v`, `+ Add` button, left sidebar view controls (`+ Edit View`, `Show/Hide Fields`, `Add Filter +`, `Add Sort By +`), data grid with inline status dropdown editor, bulk selection action toolbar.
4. **Bulk Edit Modal**
   - **Purpose:** Mass update specific fields across multiple selected session records.
   - **Components:** Title `Bulk Edit`, yellow info callout banner, `Field to update` dropdown, target field dropdown (`Status`), `Update` button, `Cancel` button.

---

## B. Feature / Capability List

1. **Session Status Management:** Support default system statuses (`Accepted`, `Accept Queue`, `Pending`, `Decline Queue`, `Declined`) with customizable display color and reorder priority.
2. **Public Status Masking (Queue Logic):** Map intermediate internal queue states (`Accept Queue`, `Decline Queue`) to a generic `Pending` indicator on participant-facing portals to prevent unintended status leaks before formal email notifications.
3. **Inline Grid Editing:** Enable direct inline editing of session statuses via table cell dropdown controls.
4. **Bulk Status Updates:** Enable multi-select record workflows with mass field modification via a dedicated "Bulk Edit" modal.
5. **Decoupled Status & Email Workflow:** Explicitly decouple status changes from auto-triggered emails to prevent accidental premature notification delivery.

---

## C. Data Model Signals

1. **Session Entity Fields:** `Title`, `Status`, `CEU Credits`, `Description`, `Starts At`.
2. **Session Status Entity Fields:** `Name`, `Category`, `Color` (hex/badge color), `Order` (integer rank), `Sessions` (count of attached records), `Created By` (`System` or user ID), `Created At`.
3. **Status Enumeration / States:**
   - `Accepted` (System Default, Order 10, Green)
   - `Accept Queue` (System Default, Order 20, Light Green, Publicly Masked)
   - `Pending` (System Default, Order 30, Yellow)
   - `Decline Queue` (System Default, Order 40, Light Orange, Publicly Masked)
   - `Declined` (System Default, Order 50, Red)

---

## D. Organizer vs Participant

* **Organizer Capabilities:** Define status configurations, edit statuses inline within submission grids, execute bulk updates, manage saved views/filters, send bulk emails.
* **Participant Capabilities:** View session submission list cards and track submission state (`Accepted`, `Declined`, or generic `Pending` indicator for queue states).

---

## E. UX/UI Craft Notes

* **Color Palette & Branding:** Primary action color is vibrant orange (`#FF6B00` / `#F26522`). Status badges follow a structured semantic color hierarchy (Green = Accepted, Light Green = Accept Queue, Yellow = Pending, Light Orange = Decline Queue, Red = Declined).
* **Grid Controls & Density:** Standard data table with compact inline editing inputs, status pills with icons, filter chips displaying real-time record counts (`View All (11)`), and dynamic bulk selection action bar overlay.
* **Modal Overlay Design:** Standard centered dialog modal featuring close action icon `X`, yellow warning context alert banner, vertical form layout (label above drop-down select input), primary orange call-to-action button, and secondary white outline dismiss button.
