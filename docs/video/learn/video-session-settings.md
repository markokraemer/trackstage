### B. Feature / Capability List

1. **Room Management:** Create, edit, and delete physical or virtual presentation locations with custom sorting order and capacity limits.
2. **Track Categorization:** Color-code and sequence overarching tracks used for agenda filtering across Day, Week, Month, List, and Room views.
3. **Tagging System:** Assign multi-purpose tags to sessions or users with color badges and custom ordering.
4. **Targeted Metadata:** Define custom Levels (expertise), Formats (presentation style), and Languages for session submissions.
5. **Speaker File Upload Rules:** Enable/disable file submission, enforce due dates, constrain file extensions, cap total file counts, enforce min/max file sizes (up to 1.95 GB), and toggle comment features.
6. **Custom Status Workflows:** Build customized session states mapped to core status categories (e.g., Pending, Accepted) that control external synchronization and speaker portal visibility.

### C. Data Model Signals

* **Room:** `id`, `name` (required), `order` (integer, optional), `capacity` (integer, optional), `sessions_count` (read-only).
* **Track:** `id`, `name` (required), `color` (hex string), `order` (integer), `sessions_count` (read-only).
* **Tag:** `id`, `name` (required), `color` (hex string), `order` (integer), `sessions_count` (read-only), `users_count` (read-only).
* **Level:** `id`, `name` (required), `order` (integer), `sessions_count` (read-only).
* **Format:** `id`, `name` (required), `order` (integer), `sessions_count` (read-only).
* **Language:** `id`, `name` (required), `order` (integer), `sessions_count` (read-only).
* **Session File Settings:** `enabled` (boolean), `due_date` (timestamp), `accepted_formats` (array of strings), `file_limit` (integer), `limit_size_enabled` (boolean), `min_file_size` (float), `max_file_size` (float), `size_unit` (enum: MB, GB), `comments_enabled` (boolean).
* **Session Status:** `id`, `name` (string, max 30 chars), `category` (enum: Pending, Accepted, Declined), `color` (hex/enum), `order` (integer), `created_by` (enum: System, User), `created_at` (timestamp).

### D. Organizer vs Participant

* **Organizer (Back-Office Admin):** Full access to create, edit, delete, and sequence Rooms, Tracks, Tags, Levels, Formats, Languages, Statuses, and File upload constraints.
* **Participant (Speaker / Attendee):**
  * **Speakers:** Upload files subject to configured limits/due dates; view assigned session status via the portal.
  * **Attendees:** Filter public agenda by Tracks, Formats, Levels, Languages, and Rooms.

### E. UX/UI Craft Notes

* **Layout Geometry:** Left-side main navigation bar with collapsible sub-item lists. Session Settings uses an internal vertical tab menu list on the left pane with main content rendered on the right.
* **Component Hierarchy:** Primary action buttons are solid orange (`#FF6B00` style) positioned at the top right. Secondary table actions use plain text blue links (`Edit` | `Delete`).
* **Modal Styling:** Center-overlay dialogs featuring vibrant blue header banners (`#1E50E6`), prominent white titles, top-right 'X' close buttons, and explicit character counter indicators (`0/255`, `10/30`).
* **Color System:** Integrated inline color indicators (small square swatches or circular badges) next to taxonomy terms to maintain consistency across backend tables and public agenda views.
